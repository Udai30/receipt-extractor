# Deploying the demo to a Hugging Face Space

Publishing is a **human action** (CLAUDE.md §4). Everything below is run by you; nothing here
is automated. Free hosting only: a **Static** Space.

## Why a Static Space (2026-10-28)

Creating a Gradio Space on free CPU was refused with `402 Payment Required`: Hugging Face now
requires a PRO subscription to host Gradio and Docker Spaces on `cpu-basic`; Static Spaces stay
free. The project is free-tier only, so the published demo is a static page and the Gradio app
runs locally (`uv run python app.py`). Decision and doc changes: WORKLOG 2026-10-28.

## What the Space shows

One `index.html`, generated by `receipt_extractor ui build-static` from the same files and
view-models as the Gradio app:

- **Results**: `reports/results.csv` (test rows) and the two charts.
- **Samples**: the six bundled CORD-v2 validation receipts with the cached A and B answers, the
  gold label, OCR text and raw JSON (`src/receipt_extractor/ui/assets/showcase/`, CC-BY-4.0).
- **Failures**: `reports/failures.csv`, counts by cause and pipeline, with a filter.

There is **no live upload**: a static page runs no model, needs no secrets and sends nothing
anywhere. No `GROQ_API_KEY` or `GEMINI_API_KEY` is set on the Space.

## 1. Build the page (repository root)

```powershell
uv run receipt_extractor report build
uv run receipt_extractor ui build-showcase
uv run receipt_extractor ui build-static
```

This writes `site/` (git-ignored): `index.html`, `README.md` (the Space card, copied from
`space/README.md`, `sdk: static`) and `assets/` (charts and sample images). To look at it locally:

```powershell
uv run python -m http.server 8765 --bind 127.0.0.1 --directory site
```

then open http://127.0.0.1:8765.

## 2. Log in and create the Space (once)

Create a **Write** token at https://huggingface.co/settings/tokens, then:

```powershell
uv run hf auth login
```

```powershell
uv run hf repos create <your-user>/receipt-extractor --type space --sdk static
```

Replace `<your-user>` with your username, without the angle brackets (`uv run hf auth whoami`
prints it).

## 3. Upload

Only the `site/` folder is sent: `.env`, `data/`, `runs/` and `.cache/` are never in it.

```powershell
uv run hf upload <your-user>/receipt-extractor site . --type space
```

## 4. Check

1. Open `https://huggingface.co/spaces/<your-user>/receipt-extractor`: the page loads with the
   headline, the results table and both charts.
2. Samples: each receipt opens, its image shows, A and B are side by side.
3. Failures: the cause and pipeline filters change the "showing" count.
4. Tell the agent the Space URL: it goes into WORKLOG, the README and the LinkedIn first comment.

To update later, repeat steps 1 and 3. To take the demo down: Space → Settings → Delete.

## Appendix: the Gradio Space (needs Hugging Face PRO)

Kept for reference only; not used while the project is free-tier only. The Gradio app (`app.py`,
`requirements.txt`) still works locally. If it were deployed on a PRO account: set the card back
to `sdk: gradio`, `sdk_version` = the tested Gradio version, `app_file: app.py`; set the
`GROQ_API_KEY` secret and `DEMO_MODE=true`, `DEMO_DAILY_REQUESTS=100`, `LOG_LEVEL=INFO`; upload
`app.py`, `requirements.txt` (`uv export --frozen --no-dev --no-hashes --no-emit-project --prune
gradio --format requirements-txt -o requirements.txt`), `src/`, `configs/models.yaml`,
`configs/pricing.yaml` and `reports/`. Gradio caps Pillow below 13 while this project pins
Pillow ≥ 13 for security; see TRD §S7 and WORKLOG M3.2 for that trade-off.
