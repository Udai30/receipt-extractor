## S1. Design principles (portfolio-wide)

1. **Results first.** The first screen shows a number someone can react to (results table / headline
   stat), not a blank input box.
2. **Show the machinery.** Every answer can expand to show its evidence: raw JSON, retrieved
   passages, generated SQL, tokens, latency, cost, model used.
3. **Honest states.** Loading, empty, error, rate-limited and low-confidence states are designed.
4. **No dead ends.** Every error says what happened and what to do next.

## S2. Visual tokens

- One `gr.themes.Base` subclass in `src/<pkg>/ui/theme.py`: neutral slate palette, one accent colour,
  `font=Inter`, `font_mono=JetBrains Mono`, radius `md`. Reuse it across projects.
- Tables: `gr.Dataframe`, fixed column order, right-aligned numbers, units in headers.
- Charts: matplotlib PNGs generated by `cli report build` (the same images go in the README), one
  consistent categorical palette, every chart has a table equivalent.
- Layout: `gr.Tabs` for top-level areas; ≤ 2 columns per tab; usable at 360 px width.

## S3. Standard states (every interactive surface)

| State | Behaviour |
|---|---|
| Idle / empty | 4–8 one-click example inputs; one sentence on what the tool does |
| Loading | Progress text naming the current stage ("Running OCR…", "Calling model…") |
| Success | Result + expandable evidence + metadata strip (model · tokens · latency · cost) |
| Partial / low confidence | Amber badge with the reason and a suggestion |
| Budget exhausted / 429 | "Live calls paused for today — showing cached results" banner |
| Error | Plain-language message + request id; no stack trace |

## S4. Accessibility

WCAG 2.2 AA contrast; keyboard-reachable controls with visible focus; colour never the only carrier
of meaning (badges carry text); charts have a table equivalent; images have alt text.

## S5. README as a UI surface

The README is the most-viewed screen. Order: headline result sentence → results table → 20–30 s
GIF → architecture diagram → how it works → evaluation method → failure list → cost & latency →
limitations → what I'd do differently → reproduce.
